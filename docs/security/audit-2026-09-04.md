**Scope:** everything that changed since the last full audit — `a44eef6..HEAD`
(2026-08-27 → 2026-09-04), i.e. the commit that carries `audit-2026-08-24.md` up to
`4a9aebc`. ~8,800 lines of new code across `core/`, `server/`, `src-tauri/`, `public/`,

**Why this audit:** the last full review predates every one of these: the Mollie card

`public/index.html`, `public/vault.js`, `public/backend.js`, `scripts/`, `.github/`;

crash-safe withdraw (M-cl-2) and the append-only quorum — are correct on the paths I

## HIGH

### H1 — `open_external` is a command-injection primitive on Windows `✓verified` · ✅ FIXED (2026-09-04)

- **Category:** security / RCE · **Platform:** Windows only (macOS/Linux/iOS/Android are fine)
- **File:** `src-tauri/src/lib.rs:2564-2573` (`open_external`), reached from
  `public/index.html:1746` (`openLink`) via `linkify` (`public/index.html`, added 0b316c5)
  and the update-gate / faucet links.

**Issue.** The Windows branch is

```rust
std::process::Command::new("cmd").args(["/C", "start", "", &url]).spawn()
```

and the only validation anywhere in the chain is a `https?://` **prefix** test
(`open_external` in Rust, `safeHttpUrl` / the faucet's `/^https:\/\/[\w.-]+/` in JS).
Rust's Windows argument quoting only wraps an argument that contains a space, tab or
quote — so a URL without a space is handed to `cmd.exe` **unquoted**, and `cmd` then
applies its own metacharacter parsing (`&`, `|`, `^`, `<`, `>`) to it.

**Impact.** A link whose URL contains `&` executes what follows it:

```
answer text:   See https://example.com/a?x=1&calc.exe for details
rendered href: https://example.com/a?x=1&calc.exe          (verified: esc → linkify → a.href)
cmd line:      cmd /C start "" https://example.com/a?x=1&calc.exe
cmd runs:      start "" https://example.com/a?x=1   AND   calc.exe
```

Arbitrary command execution in the user's session, on one click of a link the app itself
rendered. Three independent sources reach it:

1. **Model output** — since 0.4.4 answers are rendered as markdown and every `http(s)`
   run becomes an anchor. Web-grounded answers routinely quote URLs from arbitrary
   third-party pages, and a pasted page or a prompt-injected tool result gets there too.
   This is the one that matters: no hostile server required.
2. **The update gate** — `showUpdateGate` sets `a.href = safeHttpUrl(u.url)` from the
   server's `updateUrl`, and the sheet is unclosable, so the user is *told* to click it.
3. **`faucetUrl`** from the models/catalog reply (prefix-checked only).

The card checkout is the one link that is host-restricted (`safeMollieUrl`).

**Why it survived the last audit:** H1 there was about `open_external` as an *egress*
channel (seed exfil under XSS) and was closed on the seed side; the *argument handling*
was never examined, and at that time nothing turned untrusted text into anchors.

**Fix.** Use `tauri_plugin_opener` on desktop as well — it is already a dependency for
mobile and calls `ShellExecuteW` on Windows, which takes the URL as data and never goes
near a shell. Failing that: replace the `cmd /C start` invocation, and in either case
parse the URL (`Url::parse`) instead of prefix-testing it, rejecting anything whose
serialisation contains `& | ^ < > " '` or control characters. Worth also tightening
`safeHttpUrl` and the faucet-URL regex to a real parse while touching this.

**Verification.** The string chain (`esc` → `linkify` → `escAttr` → `a.href`) was run in
node; `&` survives every step. Rust's quoting rule is `std::sys::pal::windows::process`'s
`append_arg` (quote only on space/tab/quote/empty) — a URL avoids all four trivially.

**DONE (2026-09-04).** `open_external` no longer spawns anything. All four platforms go
through `tauri_plugin_opener` — already a dependency, already registered for every
platform in the builder. Checked its path down to the metal: the plugin delegates to
`open::that_detached`, and with the `shellexecute-on-windows` feature (which
tauri-plugin-opener enables) the Windows arm is `ShellExecuteExW` with the URL as
`lpFile` — no shell, no re-parse. The crate's non-Windows arms pass the URL to
`Start-Process` via an environment variable and to `open`/`xdg-open` as an argv entry;
its `cmd /c start` fallback exists only behind an `insecure` feature that is **not**
enabled in our tree (verified with `cargo tree -e features`). In front of it sits a new
`is_openable_url`: http(s) scheme, non-empty host, and no whitespace or control character
anywhere — deliberately *not* a metacharacter blocklist, so legitimate URL punctuation
(`!`, `(`, `)`, `'`, `&`) keeps working now that nothing downstream re-parses it. Test
`only_plain_http_urls_may_be_opened` pins both halves. The doc comment on the function
says why it must never become a `Command` again.

### H2 — The catalog's model rules were client-side only `✓verified` · ✅ FIXED (2026-09-04)

- **Category:** security / server-side authorization · **Found by:** the "is there any
  client-side trust?" sweep, not the diff read.
- **File:** `server/src/chat.rs` (`reserve`), `server/src/catalog.rs`
  (`provider_enabled`, `openai_model_ids`)

**Issue.** Which models a server offers was decided in `catalog.rs`, which builds the
picker: the `SCRAI_PROVIDERS` allowlist, the explicit OpenAI id list
(`SCRAI_OPENAI_MODELS`), and the testnet rule that offers **only `gpt-5.4-nano`** because
testers pay in faucet dollars while OpenAI bills us real ones. The `chat` path asked none
of them. Its only server-side guard was "does `pricing.json` price this model", and
`pricing.json` prices all three OpenAI models. The old comment on `provider_enabled` said
the quiet part out loud: *"Trims the PICKER only."*

**Impact.** A request is just JSON over the mixnet — the app is not a gatekeeper:

- On a **testnet server**, naming `gpt-5.4` in the JSON got the full model, paid for with
  $1 of faucet credit. That is our OpenAI bill, and the faucet exists to hand out $1
  invite codes.
- With `SCRAI_PROVIDERS=gemini` and an `OPENAI_API_KEY` still in the env, every OpenAI
  model stayed reachable by name — defeating the switch the operator would use precisely
  while the account is below tier 2 or has no budget cap (the OpenAI go-live conditions).
- Worst shape: `pollinations-*` are `Tier::Free`, and the free tier is served with **no
  signature, no session and no reserve**. So a disabled free-tier provider was reachable
  by an entirely unauthenticated caller.

**Fix.** `catalog::model_offered(model)` now expresses the admission decision once —
provider allowlist + the OpenAI id list — over a `provider_of_model` router that mirrors
`chat::chat`'s dispatch order exactly, so the two can't drift on who serves what.
`chat::reserve` calls it right after the price check and, deliberately, **above** the
free-tier shortcut. The decision itself is a pure function (`offered_with`) taking the
config as arguments, so its test does not write to process-global env that the other
tests in the crate read. Test:
`offered_follows_the_provider_allowlist_and_the_openai_id_list`.

The rule this leaves behind, written into the doc comment: *a restriction that only
shapes the catalog is a UI hint; if it protects money, an API key or a policy, it has to
be asked again on the path that does the work.*

## MEDIUM

### M1 — The card rail has no chargeback or refund handling `✓verified`
- **File:** `server/src/pay.rs` (`CardRail::check_status`, `Pay::settle`)
- **Issue:** `check_status` maps Mollie's status to `paid` / `expired` / `pending`, and
  everything that is not `paid | canceled | expired | failed` — including
  `charged_back` and `refunded` — falls into the `_ =>` arm as `pending`. Once an invoice
  has settled locally, nothing ever re-reads it, so a dispute or a refund at Mollie is
  invisible to the server: no clawback, no operator alert, not even a log line. The credit
  is already withdrawable as bearer ecash by then, so it is genuinely unrecoverable — but
  that is exactly why the *operator* needs to see it.
- **Impact:** card fraud is free money once, and repeat abuse of the same card/BIN goes
  unnoticed until the Mollie dashboard is read by hand. Mollie's dispute fee applies per
  case, and the network's dispute-ratio thresholds are what get a merchant account
  reviewed. Cards are the only rail with this exposure.
- **Fix:** treat `charged_back` / `refunded` explicitly — log loudly (account id prefix,
  invoice, amount), count them in the `daily` table for scrai-admin, and consider a
  post-settlement re-check of card invoices for ~120 days in the existing sweep. Before
  the live key: agree the chargeback fee with Mollie in writing (already on the
  card-payments TODO) and turn 3DS to always-on.

### M2 — Mollie settlement trusts `status` alone, not the amount `✓verified`
- **File:** `server/src/pay.rs` (`CardRail::check_status`)
- **Issue:** the reply's `amount.value` / `amount.currency` and `metadata.orderId` are
  never compared against the invoice we raised. Today the server creates the payment
  itself, stores `provider_ref` server-side and looks the invoice up by our own id, so
  there is no known path to a mismatch — this is defence in depth, not a live hole.
- **Impact:** if a payment is ever created with the wrong amount (an idempotency-key
  reuse, a currency mix-up between the `test_`/`live_` branches, a future webhook path),
  the server credits the full tile regardless.
- **Fix:** in `check_status`, return `paid` only when `status == "paid"` **and**
  `metadata.orderId` equals our reference **and** `amount.value` matches what we asked
  for in that currency. Two comparisons, no new state.

### M3 — `scrai-admin` rewrites `/opt/scrai/.env` non-atomically `✓verified`
- **File:** `server/src/bin/scrai-admin.rs:330` (`toggle_network` → `std::fs::write`)
- **Issue:** the network toggle reads the whole `.env`, rewrites it in memory and writes
  it back with a plain `std::fs::write` — truncate-then-write, no temp file, no rename, no
  backup. That file holds every provider API key, the BTCPay/Mollie keys and the Nyx
  faucet mnemonic.
- **Impact:** a crash, a signal, or a full disk between truncate and write leaves a
  truncated or empty `.env`. The server then fails to boot (or, worse, boots into a
  half-configured state), and the secrets in the lost tail are gone unless they exist
  elsewhere. It is the only file scrai-admin writes, and it is the most valuable one on
  the box.
- **Fix:** the same pattern `wallet.rs` already uses — write `.env.tmp` in the same
  directory, `fsync`, `rename` over the original, and keep one `.env.bak` from before the
  first rewrite. Also worth copying the mode/ownership explicitly rather than relying on
  the rename preserving it.

## LOW

- **L1 — a second clearnet host for the gateway picker.** `src-tauri/src/nym.rs:35`
  fetches operator monikers from `https://mainnet-node-status-api.nymtech.cc/...` from the
  user's real IP when the picker is opened. The Nym SDK already fetches
  `validator.nymtech.net` at every connect, so this is not a new *class* of leak — but it
  is a new host on a different domain (`.cc`), and "an app of ours fetches a third-party
  URL over clearnet" is precisely the C1 (Google Fonts) shape. Decide it consciously:
  confirm the host is Nym's own, and either accept it in the docs or drop the monikers.

- **L2 — `scan_events` over-counts a multi-recipient transfer.** `server/src/nyx.rs`
  checks `recipient == addr` and (testnet) `sender == pin` with `attrs.iter().any(...)`,
  then sums **every** `amount` attribute in that event. A Cosmos `transfer` event carrying
  several (recipient, sender, amount) triples — a `MsgMultiSend` — would therefore credit
  amounts that went to someone else. Not reachable with the faucet's single sends, and the
  memo still has to match, but the attributes should be walked as triples rather than
  summed independently.

- **L3 — faucet daily cap is off by one.** `scrai-faucet.rs`:
  `if claims_since(&db, day_start) > self.cfg.daily_max` allows `daily_max + 1` claims.
  `>=` (compared before the row is inserted) is what the message promises.

- **L4 — a failed faucet broadcast makes the memo permanently unclaimable.** The claim row
  is set to `stage='failed'` and kept, so the next `INSERT OR IGNORE` for that memo hits
  it and answers "this memo has already been funded" — while the error the tester just saw
  says "nothing was sent; try again in a minute". Either delete the row on a definitive
  broadcast failure or make the message say "raise a fresh invoice".

- **L5 — issued-cache eviction can re-charge a very late retry.** `MAX_ISSUED = 1024`
  (FIFO) / `ISSUED_TTL_MS = 30 days` in `pay.rs`. Each entry costs a real ticketbook, so
  forcing eviction is not cheap — but a client that comes back after 1,024 server-wide
  withdrawals (or 30 days) is treated as a fresh purchase and charged again. Fine as a
  trade-off; worth a log line when a record is evicted with `fed: None` (that one *was*
  charged and never issued).

- **L6 — a panicking redeem task never answers.** `main.rs`, redeem branch:
  `spawn_blocking(...).await.unwrap_or_else(|e| panic!(...))` panics *inside* the spawned
  task, so `crypto_tx.send` never runs and the client waits out its full timeout instead
  of getting an error. Return `Err(...)` from the join instead — the `CryptoDone` path
  already renders errors.

- **L7 — SSH ControlPath in `/tmp`.** `scripts/publish-downloads.sh:317` uses
  `ControlPath=/tmp/scrai-pub-%r@%h:%p` on a shared directory. OpenSSH refuses a socket
  with the wrong owner, so this is hygiene rather than a hole; `~/.ssh/cm-%r@%h:%p` costs
  nothing.

## Client-side trust — full sweep (2026-09-04)

Asked separately from the diff, over the whole request surface, in both directions:
**(a)** does the server ever act on something only the app checked, and **(b)** does the
app ever act on something only the server asserted? One gap found (H2 above); the rest of
the inventory, so this is re-checkable rather than a claim:

**(a) Every field a client sends, and what the server does with it**

| Field | Decides | Server-side guard |
|---|---|---|
| `model` | which provider is called, and the price | non-fallback price in `pricing.json` **+ `model_offered`** (H2) |
| `sessionId` + `counter` + `sig` + `publicKey` | who pays | `session_authorises` over the canonical body; strict `+1` counter; cached reply on an exact replay |
| `messages`, `maxTokens` | the request and the reserve | `MAX_REQUEST_BYTES`, `MAX_MESSAGES`, `maxTokens.min(MAX_OUTPUT_TOKENS)` |
| `thinkingBudget` | reasoning depth + reserve | `.min(MAX_THINKING_BUDGET)` |
| `imageSize` | picture size + reserve | mapped into `supported_image_sizes(model)`, clamped down |
| `live` | web grounding | unsigned by design; billed on the **provider's** reported query count, never the client's |
| `usd` | credit bought | signed as `invoice:{usd}`, must be in `purchase_tiers()`; credit is `usd × SCRAI_PER_USD` computed here — no client-supplied amount anywhere |
| `method` | rail | unsigned by design (it selects *how* to pay, not *how much*); `card` additionally needs `card_enabled()` and `usd ≥ card_min_usd()` — the app greys the small tiles, this is the authority |
| `testnet` | $1 faucet purchase | `is_testnet_server()`, `usd == TESTNET_USD`, rail must be `nyx`, faucet wallet pinned; settlement counts only transfers whose **sender** is the pinned faucet address |
| `fed.Withdraw` | issues a ticketbook | account signature + burned nonce, entitlement ≥ one book, not blacklisted, idempotency key bound to the paying account |
| `payment` (redeem) | credits a session | offline BLS verification + the double-spend quorum |
| `uploadId`, `invoiceId` | reads staged data / an invoice | unguessable 128-bit capability, single-use for uploads — no ownership check, none needed |
| `app` | the release gate | **client-supplied by nature.** `SCRAI_MIN_APP` is an update *nag*, not a security control — an old or hand-rolled client simply omits it. Nothing behind it is a boundary, and nothing should be put behind it. |

**(b) Where the app trusts the server, and what backs it**

- **What a turn costs** → `fair_price_estimate` recomputes it from the client's own token
  count and the bundled pricing table; > 4× fair raises `priceWarning` and `flag_server`,
  and a flagged server gets no further withdraw or auto-redeem (C3).
- **An issued credential** → `verify_share` / aggregation is checked cryptographically;
  garbage means `flag_server`, capping the loss at one book (H3).
- **"Your purse is invalid"** → not taken on the server's word: the purse's own
  verification key is compared against the server's current one, and only a genuine
  mismatch discards it. Same VK = the server is lying → flag, keep the money.
- **Images in a reply** → base64 charset validated before it can reach `imgSrc` (C1).
- **Links** (`checkout`, `faucetUrl`, `updateUrl`, and every URL in an answer) → checkout
  is host-pinned to `mollie.com`; all of them now pass `is_openable_url` and reach the OS
  browser as data, never as shell input (H1).
- **`identities` / `serverAlternates`** → only stored when the list contains the address
  the app is already using, and every entry is just another front door of that same
  server; balance and money state are unaffected by which one answers.
- **`load` in the pong** → a server could understate it to attract traffic. It only
  influences server *selection*, costs nothing, and there is one operator.

Two things are trust by construction and cannot be closed client-side: the session
**balance** is server state (the client's protection is the per-turn fair-price check plus
fixed $1/$5 denominations), and a **1-of-1 authority** can forge credentials — knowingly
accepted, see the roadmap note below.

## Checked and found sound (do not re-audit)

- **Withdraw, crash-safe (M-cl-2).** `gate_withdraw` burns the nonce, binds `req_key` to
  the `fed.Withdraw` body and refuses a body belonging to another account; the entitlement
  is consumed on the loop *before* the spawned issuance, restored on every non-issued
  outcome, and `begin_issuance` is idempotent. Concurrent same-body → "still being
  issued"; concurrent different-body with one book → the second is denied for lack of
  entitlement. A replay after issuance gets the cached credential and no second charge.
  Client side re-sends the identical body with a *fresh* nonce, which is what the server
  expects.
- **Append-only quorum.** `from_parts` derives the serial index from the record rows, so a
  restart cannot reopen a spent coin; records are written in the same transaction as the
  session/pay snapshots; a present-but-unparseable meta or row is FATAL at boot, and the
  legacy whole-snapshot migration fails closed.
- **Testnet money interlocks.** `SCRAI_TESTNET` refuses non-testnet purchases and vice
  versa; a testnet invoice must be native NYM, exactly $1, with the faucet wallet pinned,
  and `check_paid` fails closed without the pin (regression test covers both event
  shapes). `SCRAI_FAKE_PAYMENTS=1` beside any real rail is now a boot FATAL, and the
  load-test mock provider only exists on a fake-payments server.
- **Margin never leaves a release server.** `dev_audit_cost` nulls `costScrai` unless
  `SCRAI_DEV_AUDIT=1`; the daily metrics take the provider cost from the `Settled` struct
  instead of the reply.
- **Billing fix 4a9aebc** is correct — the OpenAI override now runs before the closure
  that captures `grounding_free`, with a regression test that pins it.
- **Concurrency split.** `reserve`/`run_provider`/`settle`, `begin`/`run_gateway`/`finish`
  and the crypto split all keep every money mutation on the single dispatch loop; the
  spawned halves carry no state. Semaphores + a 30 s queue wait mean a busy server refuses
  rather than piling up, and a refused chat is refunded by `settle`.
- **Native vault.** `check_id` keeps webview-supplied ids out of the path, writes are
  tmp+fsync+rename at `0600`, the key never enters JS.
- **Markdown renderer.** Escapes first and applies its regexes to already-escaped text;
  raw HTML and `javascript:` in an answer stay inert. Its only defect is the href it hands
  to `open_external` (H1) — the HTML side is sound.
- **C3/H3 client guards** (`fair_price_estimate`, `flag_server`, `is_flagged` gating
  withdraw and auto-redeem) are still wired after the refactors.

## Follow-up: the test providers were removed (2026-09-04)

Prompted by H2 — "why is pollinations still in there at all?" — Groq, Cloudflare Workers
AI and Pollinations were removed from the whole repo. They existed to develop against
without a billed key; none ever served a paying user, and each was a third party seeing
prompt content for no revenue. What went with them:

- **The unauthenticated request shape.** Pollinations was the only `Tier::Free` model, and
  that tier was the one path `chat::reserve` served with **no signature, no session and no
  reserve**. `Tier::Free` is gone from `core`, the branch is gone from `reserve`, and the
  matching unsigned client path (`free` flag → unsigned `chat` envelope, `FREE_SESSION_KEY`)
  is gone from `src-tauri` and the frontend. Every request now costs something and is
  therefore signed.
- **The silent provider fallback.** `chat::chat`'s dispatch used to end in `else { groq(…) }`,
  so any unrecognised model id reached Groq. It now ends in an explicit error, and
  `catalog::provider_of_model` returns `"unknown"` for anything unroutable — which
  `model_offered` **fails closed** on, regardless of `SCRAI_PROVIDERS`. (Two existing chat
  tests only passed because of that old fallback; they used a made-up model id and now use
  a routable one.)
- Adapters, catalog entries, the legacy TS adapters, pricing rows (14 models),
  vendor-terms entries in the app, and the provider tables in the README.

Left alone deliberately: `docs/pitch/*` (dated, published documents — rewriting history in
them would be wrong) and the earlier audit files.

**Legal:** `server/site/privacy.html` named Groq as a recipient of request content in §3
and §5. It now names **Google and OpenAI** — OpenAI is already offered (corrected by the
user 2026-09-04; the roadmap's "built, not live" note is out of date). The file carries a
checklist comment above §3: naming a recipient is a GDPR duty, so the page has to be
updated *before* a new provider serves its first request, in both worktrees, together with
`VENDOR_TERMS` in `public/index.html`.
